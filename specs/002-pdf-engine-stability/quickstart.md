**Feature**: `002-pdf-engine-stability`  
**Audience**: Package developers validating builder/layout/service fixes

---

---

## 4. Structural Byte Validation Pattern

Use generated bytes as the canonical assertion target:

```dart
final bytes = builder.generate();
expect(bytes, isNotEmpty);

final reopened = PdfDocument(inputBytes: bytes);
expect(reopened.pages.count, expectedPageCount);
reopened.dispose();
builder.dispose();
```

Use this pattern in builder/layout tests to verify:

- bytes are non-empty
- the output reopens successfully
- page count matches expectation
- no state-sync regression corrupted the final file

---

## 5. Manual Example Verification

Use the existing example documents as regression fixtures:

- `example/lib/documents/smart_space_demo_document.dart`
- `example/lib/documents/multi_grid_summary_demo_document.dart`
- `example/lib/documents/qr_attachments_demo_document.dart`

Run the example app on Windows first:

```powershell
cd example
flutter run -d windows
```

Generate the stability documents and verify:

- headers and footers never overlap content
- `newPage()` starts below the header area
- summaries after multi-page grids appear on the grid's final page or safely on the next page
- large spacing causes page breaks instead of footer overlap
- oversized images scale or fail clearly
- QR/barcode failures are explicit and do not corrupt surrounding content
- RTL and LTR layouts remain readable and non-overlapping

---

## 6. Service and Export Smoke Checks

After raw-byte generation tests pass, smoke the wrappers:

- `GeniusPdfService.generate()`
- `GeniusPdfService.generateAndSave()`
- `GeniusPdfService.generateAndOpen()`
- `GeniusPdfService.generateAndShare()`
- `GeniusPdfGenerationManager`
- `GeniusBatchExporter`

Target outcomes:

- no silent success with empty bytes
- per-job failure visibility is preserved
- batch export results remain traceable to the input sequence
- wrapper-side save/open/share/print failures surface explicit failure results

---

## 7. Exit Criteria

This feature is ready for `/speckit-tasks` only when all of the following are true:

- the stability test suite exists and passes
- `flutter analyze lib test example` passes
- example manual verification shows no header/footer overlap or stale-page summary placement
- wrapper failures surface explicit result objects instead of silent success
- any public additive API change is reflected in README and CHANGELOG
