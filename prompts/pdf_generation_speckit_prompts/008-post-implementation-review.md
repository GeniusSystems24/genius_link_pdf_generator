# 008 — Post Implementation Review Prompt

```markdown
Review the implemented changes for the PDF Generation Engine Stability feature.

Act as a senior Flutter/Dart library maintainer and PDF generation reviewer.

Review only PDF generation mechanics.

Do not review:
- financial correctness
- voucher amount correctness
- tax calculation correctness
- accounting logic correctness
- semantic correctness of user-provided data

Review checklist:

1. Scope compliance
   - Did the implementation stay focused on PDF generation?
   - Were any business calculations changed?
   - Was user-provided content modified or validated?
   - Were unrelated features added?

2. Builder state correctness
   - Is current page state always synchronized?
   - Is currentY updated safely?
   - Is page index correct after new pages?
   - Are PdfLayoutResult pages handled correctly?
   - Are multi-page components reflected in builder state?

3. Header/footer safety
   - Does remainingHeight account for footer?
   - Do new pages start below header?
   - Can content overlap header or footer?
   - Are manual reserved spaces respected?

4. Page-break behavior
   - Do text, rich text, summaries, info boxes, images, and dividers behave safely near page bottom?
   - Are impossible layouts handled with clear errors?
   - Are large images scaled or rejected predictably?

5. Grid and summary behavior
   - Does a multi-page grid update the builder final page?
   - Does a summary after a grid appear on the correct page?
   - Are multiple grids safe?

6. RTL/LTR behavior
   - Does start/end alignment respect direction?
   - Do bilingual layouts avoid overlap?
   - Are direction formats applied explicitly when needed?

7. Service and export reliability
   - Are generated bytes non-empty on success?
   - Are failures surfaced clearly?
   - Does batch generation report partial failures?
   - Is dispose handled safely?

8. Tests
   - Are there tests for each fixed defect?
   - Are regression tests included?
   - Do tests cover RTL/LTR?
   - Do tests cover portrait/landscape or constrained page space?
   - Do tests cover service failure cases?

9. Documentation
   - Is README.md updated only where needed?
   - Is CHANGELOG.md accurate?
   - Is the non-goal of business-data validation documented?

Return:
1. Overall review decision: approve / approve with notes / request changes
2. Critical issues
3. Non-critical issues
4. Missing tests
5. Risky implementation areas
6. Suggested follow-up tasks
7. Confirmation that business-data validation was not added
```
