# 006 — /speckit.analyze

```markdown
/speckit.analyze

Audit the spec, plan, and tasks for this feature.

Check for:

1. Scope drift
   - Remove any task that validates financial/business data.
   - Remove any task that changes voucher semantics.
   - Remove unrelated UI redesign tasks.
   - Remove any task that tries to correct user-provided printed values.

2. Missing PDF-generation risks
   - page state synchronization
   - header/footer overlap
   - currentY drift
   - multi-page grid final page sync
   - image overflow
   - QR/barcode rendering failure
   - empty/corrupted bytes
   - dispose/resource handling
   - batch generation failure handling
   - export/save failure handling
   - preview/print integration issues if they depend on generated bytes

3. Over-engineering
   - Do not introduce a large new architecture unless tests prove current structure cannot be fixed safely.
   - Prefer small targeted refactors.
   - Avoid replacing Syncfusion.
   - Avoid rewriting all templates.
   - Avoid broad public API changes.

4. Test coverage
   - Ensure each fix has a failing test or reproduction scenario.
   - Ensure RTL and LTR are both covered.
   - Ensure portrait and landscape are covered.
   - Ensure constrained page space is covered.
   - Ensure service failure paths are covered.
   - Ensure grid continuation pages are covered.

5. API compatibility
   - Flag any public API breaking change.
   - Require migration notes if unavoidable.
   - Prefer internal helper methods over public API changes.

6. Documentation consistency
   - README.md changes must match actual behavior.
   - CHANGELOG.md must not overclaim.
   - Documentation must clearly state that business-data validation is outside this feature.

Return:
- Critical gaps
- Over-engineered items
- Missing tests
- Tasks to remove
- Tasks to add
- Public API risk assessment
- Final go/no-go recommendation for implementation
```
