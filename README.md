# Genius Link PDF Generator

A production-oriented PDF toolkit for Flutter applications.

Genius Link PDF Generator provides a unified API for building, generating,
previewing, saving, opening, sharing, printing, and processing PDF documents.
It includes automatic page flow, RTL/LTR layout, reusable document components,
background generation, batch jobs, and dependency-injection friendly services.

Templates are available as an optional convenience layer, but they are not the
core of the package. You can build every document directly with the document
builder, the fluent report composer, or your own application-specific layer.

## Why use this package?

Most PDF libraries expose low-level drawing primitives. Genius Link PDF
Generator adds an application-level layer around those primitives so a Flutter
application can manage the complete PDF lifecycle through one consistent API.

Use it when you need to:

- generate reports, invoices, statements, receipts, forms, or certificates;
- support Arabic, English, RTL, LTR, or bilingual documents;
- keep content away from page headers and footers automatically;
- create multi-page tables, summaries, rich text, QR codes, and attachments;
- preview generated bytes inside Flutter;
- save, open, share, or print documents through platform adapters;
- merge, split, extract, rotate, inspect, or watermark existing PDFs;
- queue multiple generation jobs with priorities and retries;
- replace file, print, share, logging, or generation adapters in tests.

## Core capabilities

### Document generation

- Abstract document builder with automatic page creation.
- Precise vertical-position tracking through `currentY`.
- Footer-aware and header-aware remaining-space calculations.
- Automatic page breaks for text and reusable components.
- Portrait and landscape orientation.
- Custom page sizes, margins, compression, and layout formats.

### Language and typography

- RTL and LTR text flow.
- Arabic-compatible TrueType fonts supplied by the host application.
- Separate base, bold, header, and small font bytes.
- Bilingual-friendly alignment and component behavior.

### Reusable content

- Text and rich text.
- Headers and footers.
- Data grids and grouped tables.
- Summary sections and totals.
- Information boxes and report headers.
- QR codes and barcodes.
- Images and image attachments.
- Two-column layouts and section dividers.

### Delivery and interaction

- Generate bytes only.
- Generate and save.
- Generate and open.
- Generate and share.
- Print existing PDF bytes.
- Display PDF bytes in built-in preview widgets.

### Existing PDF processing

- Merge documents.
- Split documents.
- Extract selected pages.
- Rotate pages.
- Add text watermarks.
- Read page count, size, metadata, encryption, and signature indicators.

### Application integration

- Stable facade for common use cases.
- Backward-compatible service API.
- Application ports for generation, files, platform interaction, logging, and
  document processing.
- Explicit composition root for replacing infrastructure adapters.
- MVC controllers for generation and preview workflows.

## Installation

Add the package to your application's `pubspec.yaml`.

For a local package:

```yaml
dependencies:
  genius_link_pdf_generator:
    path: ../genius_link_pdf_generator
```

When consumed from a hosted source, use the version required by your project:

```yaml
dependencies:
  genius_link_pdf_generator: ^4.2.0
```

Run:

```bash
flutter pub get
```

The application must provide the fonts and images it wants to use. For example:

```yaml
flutter:
  assets:
    - assets/fonts/NotoSansArabic-Regular.ttf
    - assets/fonts/NotoSansArabic-Bold.ttf
    - assets/images/company_logo.png
```

Platform features such as printing, sharing, opening files, and directory access
are implemented through Flutter plugins. Complete any platform configuration
required by those plugins for the platforms your application supports.

## Choose an entrypoint

### Stable focused API

Recommended for new integrations that primarily need generation, document
operations, configuration, the builder, and preview widgets:

```dart
import 'package:genius_link_pdf_generator/genius_link_pdf_generator_api.dart';
```

This entrypoint avoids the legacy all-in-one re-exports of optional modules.

### Full backward-compatible API

Use the full entrypoint when migrating an existing project or when you need the
component library, templates, printing module, sharing module, AI module, or
experimental APIs:

```dart
import 'package:genius_link_pdf_generator/genius_link_pdf_generator.dart';
```

Existing applications can continue using `GeniusPdfService`. New code can use
`GeniusPdfClient` for package-owned result types.

## Quick start

### 1. Load a font and create a configuration

PDF fonts are byte-based. Load the font once and reuse the resulting
configuration or font bytes when creating documents.

```dart
import 'dart:typed_data';

import 'package:flutter/services.dart';
import 'package:flutter/widgets.dart';
import 'package:genius_link_pdf_generator/genius_link_pdf_generator_api.dart';

Future<GeniusPdfConfig> createPdfConfig() async {
  final regularData = await rootBundle.load(
    'assets/fonts/NotoSansArabic-Regular.ttf',
  );
  final boldData = await rootBundle.load(
    'assets/fonts/NotoSansArabic-Bold.ttf',
  );

  final Uint8List regularBytes = regularData.buffer.asUint8List();
  final Uint8List boldBytes = boldData.buffer.asUint8List();

  return GeniusPdfConfig(
    baseFontBytes: regularBytes,
    boldFontBytes: boldBytes,
    textDirection: TextDirection.rtl,
    pageSize: GeniusPdfPageSize.a4,
  );
}
```

### 2. Define a document

```dart
class SalesReportDocument extends GeniusPdfDocumentBuilder {
  SalesReportDocument({
    required GeniusPdfConfig config,
    required this.reportTitle,
    required this.lines,
  }) : super(config);

  final String reportTitle;
  final List<String> lines;

  @override
  void build() {
    addHeader(title: reportTitle);

    addLine(
      'Generated at: ${DateTime.now()}',
      font: config.smallFont,
    );

    addHorizontalLine(spacing: 12);

    for (final line in lines) {
      addLine(line);
    }

    addFooter(
      userName: 'System User',
      showPageNumber: true,
      pageNumberFormat: '{0} / {1}',
    );
  }
}
```

### 3. Generate and open the document

```dart
Future<GeniusPdfResult> createReport() async {
  final config = await createPdfConfig();
  const client = GeniusPdfClient();

  return client.generateAndOpen(
    builder: SalesReportDocument(
      config: config,
      reportTitle: 'Sales Report',
      lines: const <String>[
        'North region: 125,000',
        'South region: 98,500',
        'Total: 223,500',
      ],
    ),
    fileName: 'sales_report',
  );
}
```

The `.pdf` extension is normalized automatically. Supplying either
`sales_report` or `sales_report.pdf` does not create a duplicated extension.

## Configuration

Each document receives its own `GeniusPdfConfig`. The package does not require a
global configuration singleton.

```dart
final config = GeniusPdfConfig(
  baseFontBytes: regularFontBytes,
  boldFontBytes: boldFontBytes,
  headerFontBytes: boldFontBytes,
  smallFontBytes: regularFontBytes,
  baseFontSize: 11,
  headerFontSize: 18,
  smallFontSize: 9,
  pageSize: GeniusPdfPageSize.a4,
  orientation: PdfPageOrientation.portrait,
  textDirection: TextDirection.rtl,
  margins: PdfMargins()..all = 24,
  compressionLevel: PdfCompressionLevel.bestSpeed,
  defaultOutputPath: null,
);
```

The full entrypoint re-exports Syncfusion PDF types such as
`PdfPageOrientation`, `PdfMargins`, and `PdfCompressionLevel`. When using the
focused entrypoint, import the types required by your code explicitly if they
are not already available through your imports.

### Font fallback behavior

| Configuration value | Fallback |
|---|---|
| `boldFontBytes` | `baseFontBytes` |
| `headerFontBytes` | `boldFontBytes`, then `baseFontBytes` |
| `smallFontBytes` | `baseFontBytes` |
| `baseFontSize` | Theme body size |
| `headerFontSize` | Theme heading size |
| `smallFontSize` | Theme small size |

For Arabic or other scripts not supported by PDF standard fonts, always supply
a TrueType font containing the required glyphs.

### Loading optional assets

Use `GeniusPdfConfig.create` when the configuration should load declared asset
paths:

```dart
final config = await GeniusPdfConfig.create(
  baseFontBytes: regularFontBytes,
  boldFontBytes: boldFontBytes,
  textDirection: TextDirection.rtl,
  assetPaths: GeniusPdfAssetPaths(
    fontPaths: GeniusPdfFontPaths(
      primaryFont: 'assets/fonts/NotoSansArabic-Regular.ttf',
      secondaryFont: 'assets/fonts/NotoSansArabic-Bold.ttf',
    ),
    brandingPaths: GeniusPdfBrandingPaths(
      logo: 'assets/images/company_logo.png',
    ),
  ),
  loggerConfig: const GeniusPdfLoggerConfig(
    enabled: true,
    useConsole: true,
    minLevel: GeniusLogLevel.info,
  ),
);
```

Use `GeniusPdfConfig.createSync` when all asset bytes have already been loaded.

## Building documents

`GeniusPdfDocumentBuilder` is the central API for document creation. Override
`build()` and describe the document in drawing order.

### Automatic position tracking

The builder updates the vertical position after every supported operation.

```dart
@override
void build() {
  addLine('First line');
  addSpace(8);
  addLine('Current position: ${currentY.toStringAsFixed(1)}');

  if (!canFit(120)) {
    newPage();
  }

  addLine('Remaining height: ${remainingHeight.toStringAsFixed(1)}');
}
```

Important layout properties:

| API | Purpose |
|---|---|
| `currentY` | Current vertical drawing position |
| `remainingHeight` | Space remaining above the reserved footer |
| `canFit(height)` | Checks whether a block fits on the current page |
| `contentBounds` | Current available content rectangle |
| `headerHeight` | Space reserved by the header |
| `footerHeight` | Space reserved by the footer |
| `pageCount` | Number of created pages |
| `isRTL` / `isLTR` | Active document direction |
| `resetY([value])` | Resets the current vertical position |
| `reserveHeaderSpace(height)` | Reserves space for a custom header |
| `reserveFooterSpace(height)` | Reserves space for a custom footer |

### Common builder methods

| Method | Description |
|---|---|
| `addLine` | Adds flowing text and advances the position |
| `addTextAt` | Draws text at an absolute location |
| `addInlineText` | Draws inline text segments |
| `addHeader` | Adds a repeated page header |
| `addFooter` | Adds a repeated page footer |
| `addHorizontalLine` | Adds a divider |
| `addImage` | Adds an image with direction-aware alignment |
| `addGrid` | Adds a paginated data grid |
| `addSummary` | Adds a summary block |
| `addGridWithSummary` | Adds a grid followed by its summary |
| `addReportSummary` | Adds an overall report summary |
| `addSectionDivider` | Starts or separates a logical section |
| `addQRCode` | Adds a QR code |
| `addRichText` | Adds styled text spans |
| `addInfoBox` | Adds labeled information |
| `addReportHeader` | Adds a structured report heading |
| `addTwoColumns` | Adds a two-column custom layout |
| `addImageAttachment` | Adds a labeled inline attachment |
| `addImagePage` | Adds an image on a dedicated page |
| `addAttachments` | Adds multiple image pages |
| `addBulletList` | Adds bulleted or numbered items |

### Header and footer space

Headers and footers are included in page-flow calculations:

```dart
@override
void build() {
  addHeader(title: 'Monthly Statement');
  addFooter(
    userName: 'Admin',
    printTime: DateTime.now().toIso8601String(),
    showPageNumber: true,
  );

  for (var index = 1; index <= 100; index++) {
    addLine('Transaction $index');
  }
}
```

The content automatically continues on new pages without overlapping the
footer.

## Generating and delivering PDFs

### `GeniusPdfClient`

`GeniusPdfClient` is the recommended facade for new integrations.

```dart
const client = GeniusPdfClient();
```

| Method | Result |
|---|---|
| `generate` | Generates bytes without saving |
| `generateAndSave` | Generates and saves to the documents directory |
| `generateAndOpen` | Generates, saves, and opens the file |
| `generateAndShare` | Generates and opens the system share flow |
| `openFile` | Opens an existing file path |
| `sharePdf` | Shares existing PDF bytes |
| `print` | Prints existing PDF bytes |
| `saveToPath` | Writes bytes to a specified path |
| `shareWithOptions` | Shares with subject and text |

### Generate bytes only

```dart
final result = await client.generate(
  builder: SalesReportDocument(
    config: config,
    reportTitle: 'Sales Report',
    lines: lines,
  ),
  fileName: 'sales_report',
);
```

### Generate and save

```dart
final result = await client.generateAndSave(
  builder: SalesReportDocument(
    config: config,
    reportTitle: 'Sales Report',
    lines: lines,
  ),
  fileName: 'sales_report',
);
```

On success, `GeniusPdfSuccess.filePath` contains the saved path.

### Generate and share

```dart
await client.generateAndShare(
  builder: SalesReportDocument(
    config: config,
    reportTitle: 'Sales Report',
    lines: lines,
  ),
  fileName: 'sales_report',
  onStart: () => debugPrint('Generation started'),
  onComplete: (success) => debugPrint('Generated ${success.bytes.length} bytes'),
  onError: (failure) => debugPrint(failure.message),
);
```

### Use the backward-compatible service

Existing code can continue using `GeniusPdfService` with the same workflows:

```dart
const service = GeniusPdfService();

final result = await service.generateAndOpen(
  builder: SalesReportDocument(
    config: config,
    reportTitle: 'Sales Report',
    lines: lines,
  ),
  fileName: 'sales_report',
);
```

`GeniusPdfService` also accepts optional injected ports and callbacks for
advanced integrations and tests.

## Handling results

All generation methods return `GeniusPdfResult`.

```dart
final result = await client.generate(
  builder: document,
  fileName: 'report',
);

switch (result) {
  case GeniusPdfSuccess(:final bytes, :final fileName, :final filePath):
    debugPrint('Generated $fileName');
    debugPrint('Bytes: ${bytes.length}');
    debugPrint('Saved path: $filePath');

  case GeniusPdfFailure(:final message, :final error, :final stackTrace):
    debugPrint('PDF generation failed: $message');
    debugPrint('Error: $error');
    debugPrintStack(stackTrace: stackTrace);
}
```

Functional-style helpers are also available:

```dart
result.when(
  onSuccess: (success) => debugPrint(success.fileName),
  onFailure: (failure) => debugPrint(failure.message),
);
```

The generation application service disposes the document source after the
operation completes. Create a fresh builder for every generation attempt.

## PDF operations

The same client can process existing PDF bytes.

### Inspect a document

```dart
final info = await client.getPdfInfo(pdfBytes);

if (info != null) {
  debugPrint('Pages: ${info.pageCount}');
  debugPrint('Size: ${info.fileSizeFormatted}');
  debugPrint('Encrypted: ${info.isEncrypted}');
  debugPrint('Signatures: ${info.hasSignatures}');
}
```

### Merge documents

```dart
final cancellationToken = GeniusPdfCancellationToken();

final mergeResult = await client.mergePdfs(
  pdfBytesList: <Uint8List>[firstPdf, secondPdf, thirdPdf],
  outputFileName: 'combined_report',
  saveToFile: true,
  cancellationToken: cancellationToken,
  onProgress: (progress, message) {
    debugPrint('${(progress * 100).toStringAsFixed(0)}% $message');
  },
);

if (!mergeResult.success) {
  debugPrint(mergeResult.error);
}
```

Cancel a supported long-running operation with:

```dart
cancellationToken.cancel();
```

### Split a document

Split every ten pages:

```dart
final splitResult = await client.splitPdf(
  pdfBytes: sourcePdf,
  baseFileName: 'statement',
  pagesPerFile: 10,
  saveToFiles: true,
);
```

Or provide page ranges:

```dart
final splitResult = await client.splitPdf(
  pdfBytes: sourcePdf,
  baseFileName: 'selected_sections',
  pageRanges: const <List<int>>[
    <int>[1, 2, 3],
    <int>[4, 5],
  ],
);
```

Page numbers are validated by the document processor. Keep the numbering model
used by your application consistent when constructing page ranges.

### Extract pages

```dart
final result = await client.extractPages(
  pdfBytes: sourcePdf,
  pageNumbers: const <int>[1, 3, 5],
  outputFileName: 'selected_pages',
);
```

### Rotate pages

```dart
final result = await client.rotatePages(
  pdfBytes: sourcePdf,
  rotation: 90,
  pageNumbers: const <int>[1, 2],
  outputFileName: 'rotated_pages',
);
```

Supported rotation values are validated by the processor.

### Add a watermark

```dart
final result = await client.addWatermark(
  pdfBytes: sourcePdf,
  watermarkText: 'CONFIDENTIAL',
  opacity: 0.2,
  rotation: -45,
  fontSize: 56,
  outputFileName: 'confidential_report',
  textDirection: TextDirection.ltr,
);
```

The default runtime uses a standard PDF font for supported Latin text. To use
Arabic or another script requiring a custom font, construct a runtime or
`GeniusPdfService` with `watermarkFontBytes` containing a compatible TrueType
font.

### Generate a batch

```dart
final results = await client.generateBatch(
  builders: <({GeniusPdfDocumentBuilder builder, String fileName})>[
    (builder: firstDocument, fileName: 'report_1'),
    (builder: secondDocument, fileName: 'report_2'),
  ],
  saveToFiles: true,
  onProgress: (progress, message) {
    debugPrint('${(progress * 100).round()}%');
  },
  onItemComplete: (index, result) {
    debugPrint('Completed item $index: ${result.isSuccess}');
  },
);
```

## Reusable document components

The full package entrypoint exposes reusable PDF components. They are building
blocks, not templates: your application decides what data they contain and how
they are combined.

Common components include:

- `GeniusPdfDataGrid` for multi-page tables and grouped data;
- `GeniusPdfGridColumn` and `GeniusPdfGridRow` for table definitions;
- `GeniusPdfSummarySection` for totals and key-value summaries;
- `GeniusPdfRichText` and its builder for styled text;
- `GeniusPdfInfoBox` for structured labeled information;
- `GeniusPdfReportHeader` for company and document metadata;
- QR and barcode generators;
- image wrappers and attachment helpers;
- bullet and numbered lists;
- print themes and component style presets.

Typical composition inside a document:

```dart
@override
void build() {
  addReportHeader(reportHeader, height: 110);
  addGrid(dataGrid, spacing: 12);
  addSummary(summarySection, spacing: 16);
  addInfoBox(notesBox, spacing: 12);
  addFooter(showPageNumber: true);
}
```

The builder handles position advancement and creates a new page when a
supported block does not fit.

## Fluent report composer

For documents that do not need a dedicated subclass, use
`GeniusPdfReportComposer`.

```dart
final composer = GeniusPdfReportComposer(config: config)
  ..withHeader(title: 'Operational Report')
  ..withFooter(userName: 'Admin', showPageNumber: true)
  ..section('Overview')
  ..text('This report was built with the fluent composer.')
  ..boldText('Key metrics')
  ..line(spacing: 8)
  ..text('Orders: 320')
  ..text('Revenue: 125,000');

final result = await client.generateAndOpen(
  builder: composer,
  fileName: 'operational_report',
);
```

The composer supports text, rich text, grids, summaries, info boxes, images,
QR codes, attachments, pages, columns, and custom builder callbacks.

## Background generation

Generation methods accept `runInBackground`, which defaults to `true`.

```dart
final result = await client.generate(
  builder: document,
  fileName: 'large_report',
  runInBackground: true,
);
```

The runtime supports two paths:

1. A builder implementing `GeniusPdfBackgroundBuildSource` can provide its own
   isolate-safe generation strategy through `generateInBackground()`.
2. Existing builders use the compatibility path, with a safe foreground
   fallback when a builder cannot be transferred to a background isolate.

For small documents or when debugging platform/isolate behavior, explicitly use:

```dart
runInBackground: false
```

Never reuse a builder after a generation call. Generation disposes it whether
the operation succeeds or fails.

## Batch generation and job queues

For simple lists, use `GeniusPdfClient.generateBatch`. For scheduling,
priorities, retries, cancellation, and concurrent processing, use
`GeniusPdfGenerationManager` from the full entrypoint.

```dart
final manager = GeniusPdfGenerationManager(
  config: const GeniusPdfGenerationManagerConfig(
    maxConcurrentJobs: 2,
    defaultRunInBackground: true,
    retryFailedJobs: true,
    maxRetries: 2,
  ),
);

final jobId = await manager.addJob(
  builder: createReportBuilder(),
  builderFactory: createReportBuilder,
  fileName: 'scheduled_report',
  priority: GeniusPdfJobPriority.high,
  autoOpen: false,
  onComplete: (result) {
    debugPrint('Saved to ${result.filePath}');
  },
  onError: (failure) {
    debugPrint(failure.message);
  },
);

final job = manager.getJob(jobId);
debugPrint('${job?.status}');
```

A `builderFactory` is required for safe retries or repeated scheduled jobs,
because a builder is disposed after each attempt.

The manager supports:

- priority queues;
- configurable concurrency;
- pause and resume;
- cancellation;
- retry policies;
- delayed and recurring jobs;
- job update streams;
- queue statistics;
- batch submission.

Dispose long-lived managers when the owning application scope ends.

## Dependency injection and testing

The default runtime is available through:

```dart
GeniusPdfCompositionRoot.defaults
```

Create a custom runtime when your application needs alternative adapters:

```dart
final runtime = GeniusPdfCompositionRoot.create(
  documentGenerator: fakeGenerator,
  fileGateway: inMemoryFileGateway,
  interactionGateway: fakeInteractionGateway,
  documentProcessor: fakeDocumentProcessor,
  logger: testLogger,
);

final client = GeniusPdfClient(runtime: runtime);
```

The core extension points are:

| Port | Responsibility |
|---|---|
| `GeniusPdfDocumentGenerator` | Converts a build source into PDF bytes |
| `GeniusPdfFileGateway` | Reads, writes, and resolves directories |
| `GeniusPdfInteractionGateway` | Opens, shares, and prints PDFs |
| `GeniusPdfDocumentProcessor` | Merges, splits, rotates, inspects, and watermarks |
| `GeniusPdfLogPort` | Receives application and infrastructure logs |

The backward-compatible `GeniusPdfService` constructor also accepts these ports
and individual platform callbacks.

## Architecture

The operational core follows this dependency direction:

```text
Flutter Views / Public Facades
             ↓
        MVC Controllers
             ↓
     Application Services
             ↓
           Domain
             ↑
Infrastructure implements Application ports
```

Main responsibilities:

- **Domain:** result models, delivery models, document-operation models, and
  framework-independent business concepts.
- **Application:** generation and processing use cases plus abstract ports.
- **Infrastructure:** Syncfusion generation/processing and Flutter platform
  adapters.
- **Presentation:** preview views and controllers.
- **Composition:** creates the default runtime and connects implementations.
- **Public API:** stable facade and compatibility wrappers.

## Optional modules

The full entrypoint includes additional modules that are not required for the
basic generation workflow.

### Printing

The printing module adds printer discovery, settings, profiles, print preview,
and job tracking. Basic printing of generated bytes is already available through
`GeniusPdfClient.print`.

### Sharing

The sharing module provides higher-level sharing workflows such as email,
application targets, Bluetooth-related flows, and sharing history. Basic system

### Export

### AI and experimental v2 APIs

## 4.2.0 transaction-transfer exports

Version 4.2.0 adds two landscape PDF reports for the
`transaction_transfer` accounting-leg dataset:

- `MultiTransactionTransferPdf` — movements across multiple accounts.
- `MultiTransactionTransferForAccountPdf` — movements for one account with an
  opening balance and running current balance.

Both templates use `(serviceId, transactionId)` as the logical transaction
reference. A source row's signed `amount` controls accounting direction:
positive values are Debit and negative values are Credit. Counter-account
arrays in `description` are shown as metadata and do not override the signed
movement direction.

### Multi-account transfer report

`MultiTransactionTransferPdf` renders one affected account per grid row. The
main columns are date, reference, service, account, Debit, Credit, and
Description. Transfer or commission type is prefixed to the note in the
Description column.

Currencies are separated using group headers and per-currency total rows. The
grid therefore does not repeat a `Currency / العملة` column on every row.

```dart
final report = MultiTransactionTransferPdf(
  config: pdfConfig,
  meta: TransactionTransferDocumentMeta(
    title: 'Transaction Transfers',
    titleAr: 'حركات التحويلات',
    issueDate: DateTime.now(),
    exportingUserName: 'System User',
  ),
  rows: TransactionTransferJsonData.rowsFromJson(transactionTransferJson),
  services: TransactionTransferJsonData.servicesFromJson(servicesJson),
  configuration: TransactionTransferReportConfiguration(
    periodStart: DateTime(2026, 8, 1),
    periodEnd: DateTime(2026, 9, 30),
    showTotals: true,
  ),
  reportId: 'TRF-2026-09',
  showQRCode: true,
  showNotes: true,
);
```

### Account transfer report

`MultiTransactionTransferForAccountPdf` filters the same source rows to one
account. Provide `openingBalances` from the ledger immediately before the report
period. Balances use the same signed convention as the source rows: positive is
Debit and negative is Credit.

Each currency starts with an opening-balance row. The report then applies every
signed movement in chronological order and displays `Current Balance / الرصيد
الحالي` after the operation. Currencies remain visually separated by group
headers rather than a repeated currency column.

```dart
final report = MultiTransactionTransferForAccountPdf(
  config: pdfConfig,
  meta: TransactionTransferDocumentMeta(
    title: 'Account Transfer Movements',
    titleAr: 'حركات تحويلات الحساب',
    issueDate: DateTime.now(),
    exportingUserName: 'System User',
  ),

  accountId: 2305,
  services: TransactionTransferJsonData.servicesFromJson(servicesJson),

    'YER': 125000,

    periodEnd: DateTime(2026, 9, 30),

```

The transaction-transfer JSON does not contain opening ledger balances, so the

commission filtering, semantic Debit/Credit cell colors, QR/report notes, and a
repeating footer with exporting user, issue date, and page number.

## 4.1.0 Account export templates

Version 4.1.0 adds a dedicated account-export family for exporting one or many
ledger accounts to PDF or image output. The four templates share only their
account/configuration models; each template owns its complete document drawing
implementation so changes to one export format do not implicitly change the
others.

The account-export APIs are available from the full package entrypoint:

```dart
import 'package:genius_link_pdf_generator/genius_link_pdf_generator.dart';
```

They can also be imported from the focused account-export barrel:

```dart
import 'package:genius_link_pdf_generator/templates/account_export/account_export.dart';
```

### Available account exports

| Template | Output | Page orientation | Activity support | Primary use |
| --- | --- | --- | --- | --- |
| `SingleAccountPdf` | PDF | Portrait | Summary and detailed | Full statement for one account, including multiple currencies |
| `MultiAccountPdf` | PDF | Landscape | Summary in the account grid | Large account lists, grouping, balances, movement, and totals |
| `SingleAccountImage` | Image | Portrait source page | Summary only | Compact shareable snapshot for one account and one selected currency |
| `MultiAccountImage` | Image(s) | Landscape source page | Summary only | Compact account tables split into bounded image-sized chunks |

### Shared account-export models

The four templates reuse the models in
`lib/templates/account_export/models.dart`, including:

- `AccountExportDocumentMeta` for title, issue date, and exporting-user data;
- `AccountExportConfiguration` for field visibility, period, selected currency,
  balances, activity, grouping, totals, and semantic amount colors;
- `AccountExportFieldVisibility` for enabling optional account fields;
- `AccountExportActivityMode` for summary or detailed PDF activity;
- `AccountExportGrouping` for no grouping, account-group grouping, or
  parent-account grouping;
- account, balance, activity-summary, and transaction data models used by the
  four renderers.

Rendering helpers are intentionally **not** shared. Each of
`single_account_pdf.dart`, `multi_account_pdf.dart`,
`single_account_image.dart`, and `multi_account_image.dart` contains its own
layout/grid/summary/footer drawing logic. This keeps each exported document
independent while preserving a common data contract.

### SingleAccountPdf

`SingleAccountPdf` is designed for a full account statement. It uses a
bilingual-split report header and a three-column minimal information block for
account metadata. When multiple currencies are supplied and no
`selectedCurrency` is forced, each currency is rendered separately in this
order:

1. account balance for the currency;
2. account activity summary for the currency;
3. detailed transaction grid for the currency when detailed mode is enabled.

The transaction grid supports transaction number/date/type, a wrapping full
description, currency, debit, credit, and running balance. Debit and credit
amount cells use separate subtle semantic colors. The report also supports a
QR verification block, report notes, and a repeating footer with exporting-user
information, issue date, and page numbering.

### MultiAccountPdf

`MultiAccountPdf` uses landscape orientation to prioritize table readability.
Its report details are rendered in a three-column minimal information block and
can include report name, report period, report currencies, and account count.
The main grid supports account hierarchy fields, group/nature/contact fields,
selected-currency balance, debit movement, credit movement, and the last
transaction date.

The report can group accounts by account group or parent account and can render
subtotals/grand totals. Group subtotal rows place the group name in the account
name column for easier scanning. Per-account detailed transaction tables are
not rendered in this template; movement remains summarized in the main grid.
QR/report notes and the repeating user/date/page footer follow the same report
conventions used by the trial-balance template.

### Image exports

Image templates intentionally remain summary-only so their output stays compact
and legible. They use the package's existing PDF-to-image/export flow rather
than a separate rasterization implementation.

`SingleAccountImage` renders one account for one selected currency and allows
optional account fields to be hidden when a smaller image is required.

`MultiAccountImage` requires callers to bound the number of accounts rendered
in one image through `maxAccountsPerImage`. For larger datasets, use
`MultiAccountImage.split(...)` to create multiple independently renderable
chunks instead of shrinking an unbounded table into a single image.

### Debit and credit semantics

All account-export tables that contain debit and credit amounts style the amount
cells themselves, not only their headers. The default palette uses a subtle
semantic background plus a matching foreground color for each side while
maintaining readable contrast. Supply `AccountExportAmountColors` through
`AccountExportConfiguration.amountColors` when an application needs a custom
palette.

### Configuration example

The same configuration model can be reused across the account-export family:

```dart
const configuration = AccountExportConfiguration(
  fields: AccountExportFieldVisibility.multiPdf,
  selectedCurrency: 'YER',
  showBalances: true,
  showActivity: true,
  activityMode: AccountExportActivityMode.summary,
  grouping: AccountExportGrouping.accountGroup,
  showTotals: true,
);
```

For image templates, keep `activityMode` set to
`AccountExportActivityMode.summary`. `MultiAccountImage` also requires a
selected currency whenever balance or activity values are visible.

## 4.0.0 — S03 Flow Layout & Pagination Engine

Sprint S03 adds a deterministic two-pass page-flow engine for long ERP
documents while keeping the current builder API compatible.

The core model is:

```dart
final section = PdfFlowSection(
  firstPageHeader: const PdfTextBand(
    text: 'FIRST PAGE',
    textAr: 'الصفحة الأولى',
    placement: PdfBandPlacement.top,
    kind: PdfBandKind.pageHeader,
  ),
  pageHeader: const PdfTextBand(
    text: 'ERP REPORT',
    textAr: 'تقرير ERP',
    placement: PdfBandPlacement.top,
    kind: PdfBandKind.pageHeader,
  ),
  pageFooter: const PdfPageNumberBand(),
  repeatableBands: const [
    PdfRepeatableBand(
      id: 'table-header',
      placement: PdfBandPlacement.top,
      kind: PdfBandKind.tableHeader,
      child: PdfFixedBlock(height: 24),
    ),
  ],
  blocks: [
    PdfTextBlock(
      text: 'Long notes...',
      minOrphanLines: 2,
      minWidowLines: 2,
    ),
    PdfKeepTogether(
      PdfFixedBlock(height: 120),
    ),
  ],
);
```

Plan without rendering:

```dart
final plan = builder.planFlowSection(section);

print(plan.pageCount);
print(plan.pages.first.availableBodyHeight);
```

Then render the exact plan:

```dart
final result = builder.addFlowSection(
  section,
  plan: plan,
);
```

The engine supports:

- `keepTogether`;
- `keepWithNext`;
- `pageBreakBefore`;
- `pageBreakAfter`;
- conditional breaks;
- orphan/widow-aware built-in text/list splitting;
- repeated section/group/table headers and footers;
- first-page header and last-page footer variants;
- section-level landscape/custom page sizes;
- Page X of Y bands;
- document status/original-copy marker bands;
- deterministic `currentY`;
- measurement caching so drawing callbacks are not executed during planning.

Existing `addLine`, `addHeader`, `addFooter`, `addTwoColumns`, component
methods, and custom callbacks remain valid. Existing `(PdfPage, Rect)`
callbacks can be wrapped with `PdfLegacyCallbackBlock`.

`GeniusPdfReportComposer` also supports:

```dart
GeniusPdfReportComposer(config: config)
    .flowSection(section)
    .buildPdf();
```

The example Dashboard includes **S03 Flow Layout** with 1-page, 50-row,
500-row, long-note, keep-together, repeated-band, metadata, custom-landscape
and compatibility scenarios in both LTR and RTL.

See `docs/sprints/s03/FLOW_LAYOUT_CONTRACT.md` for the complete contract.

## 4.0.0 — S06 ERP Shared Domain & Calculation Layer

S06 introduces reusable ERP models for transaction documents:

```dart
final context = ErpDocumentContext(
  organization: const ErpOrganization(
    id: 'ORG-1',
    legalName: 'Genius Systems',
  ),
  identity: ErpDocumentIdentity(
    kind: ErpDocumentKind.invoice,
    number: 'INV-2026-0001',
    issueDate: DateTime(2026, 9, 4),
  ),
  documentCurrency: ErpCurrency.sar,
  lineItems: [
    ErpLineItem(
      id: '1',
      description: 'Consulting',
      quantity: const ErpQuantity(
        value: 2,
        unit: ErpUnit.each,
      ),
      unitPrice: ErpMoney.fromAmount(
        100,
        currency: ErpCurrency.sar,
      ),
      taxes: const [
        ErpTaxLine(code: 'VAT', ratePercent: 15),
      ],
    ),
  ],
);
```

Quotation, Purchase Order and Invoice use the same context and line model.

```dart
final result = const ErpCalculationService().calculate(
  ErpCalculationRequest.fromContext(
    context,
    documentDiscounts: [
      ErpDiscount.percentage(percentage: 10),
    ],
    config: const ErpCalculationConfig(
      documentDiscountTaxPolicy:
          ErpDocumentDiscountTaxPolicy.beforeTax,
    ),
  ),
);
```

The result provides subtotal, line/document discounts, charges, taxable amount,
tax totals, grand total, rounding adjustment and optional paid/due values.

explicit `ErpExchangeRate`; base-currency totals are returned separately.

`ErpDomainValidator` validates zero/negative policies, currencies, adjustments,
taxes and exchange rates. Optional metadata remains nullable. Serialization is

## Troubleshooting

### Arabic characters are missing or disconnected

Use a TrueType font that contains Arabic glyphs and pass its bytes through
`baseFontBytes`. Do not rely on standard PDF fonts for Arabic content.

### The document was generated but not opened, shared, or printed

Generation and platform interaction are separate steps. Confirm that:

- the operation returned `GeniusPdfSuccess`;
- the target platform supports the requested plugin operation;
- required platform permissions and plugin setup are complete;
- the application is not running in a test environment without platform
  channels.

Inject fake gateways for widget and unit tests instead of invoking plugins.

### Content overlaps the footer

Use `addFooter`, `reserveFooterSpace`, and builder-managed methods. Custom
absolute drawing through the underlying page graphics does not automatically
advance `currentY` unless your code updates or resets the position.

### A builder fails during background generation

Try `runInBackground: false`. For custom isolate-safe generation, implement
`GeniusPdfBackgroundBuildSource` and move the transferable generation logic into
`generateInBackground()`.

### A retry fails or reuses an invalid builder

Provide `builderFactory` when configuring retries or recurring jobs. Every
attempt must receive a fresh builder.

### A watermark cannot render Arabic text

Pass compatible `watermarkFontBytes` through a custom `GeniusPdfService` or
runtime. Standard PDF fonts do not contain all Arabic glyphs.

### The analyzer cannot find an old import

Use one of the supported package entrypoints:

```dart
import 'package:genius_link_pdf_generator/genius_link_pdf_generator_api.dart';
```

or:

```dart
import 'package:genius_link_pdf_generator/genius_link_pdf_generator.dart';
```

## Migration and compatibility

Version 3.7 keeps the existing `GeniusPdfService` API and legacy full entrypoint.
New applications can adopt `GeniusPdfClient` gradually without rewriting their
document builders.

Typical migration:

```dart
// Existing code
const service = GeniusPdfService();
final oldResult = await service.generate(
  builder: builder,
  fileName: 'report',
);

// New facade
const client = GeniusPdfClient();
final newResult = await client.generate(
  builder: builder,
  fileName: 'report',
);
```

Do not use the same builder instance in both calls; each generation disposes the
builder.

See [`MIGRATION.md`](MIGRATION.md) for architecture and compatibility details,
and [`CHANGELOG.md`](CHANGELOG.md) for version history.
